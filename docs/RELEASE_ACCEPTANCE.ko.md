# 데스크톱 출시 검증

이 정책은 Chemvas 첫 공개 안정 데스크톱 릴리스를 내보내기 전에 충족해야 할 조건을
정합니다. 승인되었다고 해서 어떤 플랫폼이 준비되었다는 뜻은 아니며, 릴리스 완료
여부는 맨 끝의 기록표에만 남깁니다. 릴리스 절차: [RELEASING.ko.md](../RELEASING.ko.md).
문서 형식 보장 범위: [DOCUMENT_COMPATIBILITY.ko.md](DOCUMENT_COMPATIBILITY.ko.md).
영문: [RELEASE_ACCEPTANCE.md](RELEASE_ACCEPTANCE.md).

## 대상 플랫폼

| 행 | 플랫폼 | 아키텍처 | 패키지 |
| --- | --- | --- | --- |
| W1 | Windows 11 25H2 | 네이티브 x64 | GUI와 CLI를 포함한 사용자별 Inno Setup EXE |
| W2 | Windows 11 26H2 | 네이티브 x64 | GUI와 CLI를 포함한 사용자별 Inno Setup EXE |
| M1 | macOS 26 | Apple Silicon arm64 | DMG에 담긴 독립 실행형 `Chemvas.app` |
| L1 | Ubuntu 24.04 LTS, GNOME Wayland 세션 | x86_64 | 독립 실행형 tar.gz, 사용자별 실행기, 데스크톱·MIME 연동 |
| L2 | Ubuntu 24.04 LTS, GNOME X11 세션 | x86_64 | L1과 같은 패키지 |

모든 패키지에는 Python이 포함되며, OS 시스템 런타임 라이브러리는 문서화된 사전
요구 사항이 있을 수 있습니다. 모든 바이너리 아티팩트는 계획된 결과물이며, 이 문서가
인증하는 것은 없습니다. 바뀌지 않는 것: 기존 0.27.1 PyPI 설치는 계속 제공되고,
Python 요구 사항은 `>=3.12` 그대로이며, 제품 런타임 최소 요구 사항도 바뀌지 않습니다.

Intel Mac, Windows ARM, Linux ARM, 그 밖의 OS나 배포판 버전은 이번 릴리스에서
인증하지 않지만 일부러 막지도 않습니다. 어떤 행이 통과하지 못하면 릴리스를 미루거나
범위 변경을 결정하고 공개합니다. 범위를 조용히 줄이지 않습니다.

## 모든 행에 적용되는 규칙

- 모든 행에 같은 검증 기준을 적용합니다. W1과 W2, L1과 L2는 각각 따로 통과해야
  하며, 하나가 통과했다고 다른 하나도 통과한 것으로 보지 않습니다.
- 정확한 OS 빌드 또는 포인트 릴리스, CPU, 디스플레이 백엔드, Python·PyQt·Qt·
  Pillow·PyInstaller 버전, 글꼴, 후보 git SHA, 아티팩트 SHA256을 기록합니다.
- 테스트 전에 후보 식별 정보를 고정합니다. 앱이 바뀌면 영향받는 증거는 무효가 되며
  다시 실행합니다.
- 고정된 후보에서 실제로 실행한 검사만 통과로 기록합니다. 공개하는 아티팩트 해시는
  테스트한 아티팩트 해시와 같아야 합니다.

## 증거 단계

어떤 검사도 자기 결과에 의존하지 않도록 단계를 분리합니다.

1. **소스 테스트**는 후보 git SHA에서 실행합니다. 소스 동작을 증명할 뿐, 독립 실행
   패키지의 설치나 실행을 증명하지 않습니다.
2. **후보 검증**은 공개 릴리스 전에, 공지하지 않은 통제된 다운로드로 받은 빌드
   아티팩트에서 SHA256을 확인한 뒤 실행합니다. 아래의 행별 검사는 모두 이 단계입니다.
3. **공개 다운로드 스모크 검사**는 공개 후 최종 공개 다운로드에서 실행합니다. 공개된
   SHA256이 검증된 아티팩트와 같은지, 앱이 설치·실행되는지 확인합니다. 실패하면 공개하고
   [RELEASING.ko.md](../RELEASING.ko.md)에 따라 처리하며, 후보 검증을 대신하지 않습니다.

## 진행 순서

1. 후보 git SHA와 의존성 버전을 고정합니다.
2. 소스 테스트.
3. 아티팩트를 빌드하고 SHA256을 기록합니다.
4. 플랫폼별 서명과 공증(계정 준비는 외부 의존 요소일 수 있음).
5. 행별 후보 검증: 깨끗한 환경 설치, 예제 파일, 안전성, 원고 출력.
6. 실제 번들의 타사 의존성 목록·라이선스 고지·재배포 조건 확인.
7. 출시 결정, 검증된 아티팩트를 그대로 공개.
8. 공개 다운로드 스모크 검사와 공개 보고.

## 소스 테스트

- 각 네이티브 OS에서(Windows는 Git Bash) 전체 테스트 범위로 `make check`를 실행하고
  줄·분기 커버리지를 각각 기록합니다. 100% 커버리지를 요구하는 것은 아닙니다.
- CI의 quality, package-smoke, secret-scan 작업은 유지하고 새 OS CI는 추가하지 않습니다.
- 헤드리스나 WSL 실행은 네이티브 GUI를 증명하지 않습니다.

## 서명과 OS 보호

- Windows(W1, W2): 설치 파일에 서명하고, 경고와 서명 동작을 기록합니다.
- macOS(M1): 서명과 공증을 하고, 내려받은 DMG의 격리(quarantine)·서명·공증 동작을
  기록합니다.
- Linux(L1, L2): 공증은 없으며, 사용자는 공개된 SHA256을 확인합니다.
- 각 동작은 문서화된 지원 설치 절차로 해결합니다. 안내문에서 OS 보안 보호 기능을
  끄라고 요구하지 않습니다.
- 서명이나 공증 계정을 기다리는 행은 대기 상태로 둡니다.

## 깨끗한 환경 설치

별도로 설치한 Python, 소스 체크아웃, 개발용 PATH 항목이 없는 새 사용자 계정이나
VM을 사용합니다.

1. 통제된 다운로드로 아티팩트를 받고 SHA256을 확인합니다.
2. 설치한 뒤 OS의 일반적인 진입점으로 Chemvas를 실행합니다.
3. 파일 연결로 문서를 엽니다. 유니코드 문자와 공백이 있는 경로도 포함합니다.
4. GUI에서 편집, 실행 취소, 다시 실행, 저장, 종료, 다시 열기, 내보내기를 합니다.
5. 이전 빌드 위에 업데이트하고 문서와 설정이 유지되는지 확인합니다.
6. 제거한 뒤 사용자 문서는 남고 Chemvas 소유 연동만 지워졌는지 확인합니다.

## 예제 파일

공개용 합성 예제 다섯 개와 실행 명령, 기대 결과 기준은
[../examples/release-validation/README.ko.md](../examples/release-validation/README.ko.md)에 있습니다.

| 파일 | 기대 내용 |
| --- | --- |
| `01-basic.cdxml` | 아래첨자가 있는 MnO2 라벨을 단 기본 화살표 |
| `02-reactants.cdxml` | 구조 세 개, 플러스 연결자, 따로 놓인 캡션 1, 2, 3 |
| `03-notation.cdxml` | 전하, 쐐기·해시 결합, 위첨자와 아래첨자 |
| `04-mixed.cdxml` | 그룹, 서식 있는 메모, 이미지, 도형 |
| `05-native.cdxml` | 보존되어야 하는 네이티브 전용 서식 조각과 텍스트 |

`05-native.cdxml`은 Chemvas 스냅샷 없이 직접 작성한 합성 네이티브 CDXML이며 실제
ChemDraw 출력이 아닙니다. 예제 파일은 기대한 편집 상태와 출력을 확인할 뿐, 반응
화학을 검증하지 않습니다. 실제 ChemDraw 가져오기·내보내기·왕복 검증은 별도 증거이며
대기 중입니다. 실제 샘플은 사본으로만 다루고, 허락 없이 커밋하지 않습니다.

## 안전성 검사

격리된 임시 디렉터리에서 버려도 되는 문서 사본만 사용합니다. 디스크 가득 참 검사는
폐기 가능한 VM이나 크기를 제한한 테스트 볼륨에서 수행하며, 호스트의 일반 데이터
볼륨을 채우지 않습니다.
소스 증거는 [test_cdxml_working_documents.py](../tests/test_cdxml_working_documents.py)와
[test_save_recovery_lifecycle.py](../tests/test_save_recovery_lifecycle.py)입니다.
소스 테스트는 행마다 설치된 앱에서 격리하여 수행하는 수동 재현을 대신하지 않으며,
이 재현은 여전히 필요합니다.

- 저장 실패: 읽기 전용 폴더, 잠긴 파일, 디스크 가득 참으로 저장을 실패시킵니다.
  원본 파일의 SHA256을 전후로 기록하며, 원본 바이트가 같을 때만 통과입니다.
- 중단된 세션: 편집 중 프로세스를 강제 종료한 뒤 다시 실행하면 복구를 제안하고,
  문서가 손상되지 않습니다.
- 외부 편집: 열려 있는 파일을 다른 프로그램이 바꾸면, Chemvas가 덮어쓰기 전에
  이를 감지합니다.

CLI 검증은 GUI 실행 취소나 복구를 증명하지 않습니다.

## 원고 출력

- SVG, PDF, PNG를 84 mm와 174 mm 폭으로, PNG는 300 dpi로 내보냅니다.
- 문서 상태를 의미 단위로 확인한 뒤, 렌더링된 기호와 치수를 확인합니다.
- 결과물을 실제 원고에 넣고 변경과 무관한 사람이 시각적으로 검토합니다. OS 간 픽셀
  단위 동일성은 약속하지 않으며, 외부 편집기에서의 편집은 별도의 지원 범위입니다.

## 출시 기준과 보고

데이터 손실, 화학적 의미 변경, 열기 실패, 잘못된 출력, 설치 실패, 핵심 조작 실패가
하나도 없을 때만 출시합니다. 새 기능은 다음 릴리스로 미룹니다. 실제 번들에 포함된
타사 의존성의 목록·라이선스 고지·재배포 조건을 확인하고 결과를 기록합니다. 이 검토는
아직 미완료입니다.
각 검사는 통과, 실패, 대기, 건너뜀 중 하나로 이유와 함께 공개합니다. 필수 검사를
건너뛴 것은 통과가 아닙니다.
